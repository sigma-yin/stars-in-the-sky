# RMTC 2026 现场操作备忘

比赛日：2026-11-01（线下）
镜像：`rmtc-team:20261029`（提交包 `rmtc-team-image.tar.gz`，251 MB）
节点：`rmtc_bot`，由镜像 ENTRYPOINT `./run_contestant.sh` 启动

## 0. 一句话流程

导入镜像 → 填 4 个现场值 → `docker run -d` → 看日志确认 seat/domain/gateway 正确 →
裁判开赛，节点自动收感知、出动作。全程不需要调用任何 `/api/*`。

## 2. 到场后（T-60 分钟）

1. 找主办方确认 4 个值并**写在纸上**：

   | 项目 | 值 |
   | --- | --- |
   | 席位 `RMTC_SEAT` | |
   | 席位令牌 `RMTC_TEAM_TOKEN` | |
   | 网关地址 `RMTC_AI_URL`（完整 completions 地址） | |
   | ROS 域 `ROS_DOMAIN_ID` | |

   注意：镜像内默认 `ROS_DOMAIN_ID=27` 是练习值，现场不同必须 `-e` 覆盖。
   网关地址必须包含 `/v1/chat/completions` 这一段。

2. 校验并导入镜像：

```bash
sha256sum -c rmtc-team-image.tar.gz.sha256
gunzip -c rmtc-team-image.tar.gz | docker load
docker images | grep rmtc-team
```

3. 确认镜像健康（不接裁判也能跑）：

```bash
docker run --rm rmtc-team:20261029; echo "退出码=$?"   # 应打印缺少令牌并以 2 退出
```

## 3. 开赛（T-10 分钟）

```bash
export RMTC_SEAT=A
export RMTC_TEAM_TOKEN='现场令牌'
export RMTC_AI_URL='现场网关完整地址'
export ROS_DOMAIN_ID=27

docker run -d --name rmtc_a --network host \
  -v /现场路径/decision_config.json:/work/rmtc_ws/decision_config.json \
  -e RMTC_SEAT="$RMTC_SEAT" \
  -e RMTC_TEAM_TOKEN="$RMTC_TEAM_TOKEN" \
  -e RMTC_AI_URL="$RMTC_AI_URL" \
  -e ROS_DOMAIN_ID="$ROS_DOMAIN_ID" \
  rmtc-team:20261029
```

要点：

- `--network host` 必须有；不要加 `--ipc=host`、`--privileged`，镜像已内置 UDP-only 的 Fast DDS 配置。
- `-d` 后台运行，终端断了不掉；容器名固定 `rmtc_a`，方便查日志和停止。
- `-v` 那行是为了现场能改 `decision_config.json`；不挂载也能跑，但切换模式要 `docker exec` 进去改。
- 一个席位只起一个容器。别为了"保险"起两个，同席位重复发布动作会被判无效。

## 4. 起跑检查（30 秒内看完）

```bash
docker ps | grep rmtc_a                  # Up
docker logs rmtc_a | head -5             # seat= / domain= / gateway= 三个值对不对
docker logs -f rmtc_a                    # 每 Tick 应有 pos/hp/res/send
```

```bash
docker exec rmtc_a bash -c 'source /opt/ros/humble/setup.bash && ros2 topic list | grep team'
```

应看到 `/team_A/perception` 与 `/team_A/action`。

判定标准：日志出现第一帧感知后，`send` 开始逐 Tick 输出 = 正常。
只看到 `seat=` 一行、没有后续 = 没收到感知，按第 7 节排查。

## 5. 比赛中的操作

- 只允许改 `decision_config.json` 的 `decision_type`（`collect` / `survive`），暂停期间改，恢复后 20 Tick 内生效。
- 不进容器、不重启、不 `docker rm`、不改环境变量。
- 用 `docker logs -f rmtc_a` 或 `docker logs rmtc_a > bot.log 2>&1` 持续留档。
- 若需要临时停：`docker stop rmtc_a`，恢复前用第 3 节同一命令重新起（令牌不变）。

## 6. 结束后

```bash
docker logs rmtc_a > bot_现场_$(date +%H%M).log 2>&1
docker stop rmtc_a
```

保留日志与当场的 `decision_config.json`，复盘用。

## 7. 故障速查

| 现象 | 最可能原因 | 处理 |
| --- | --- | --- |
| 启动即退出，日志"缺少 RMTC_TEAM_TOKEN" | 令牌没传或变量为空 | 重新 `docker run`，检查引号 |
| 容器 Up 但没有感知 | `ROS_DOMAIN_ID` 与裁判不一致 | 用现场通知的值覆盖后重起 |
| 有感知但车辆不动 | 席位值与令牌不匹配 | 核对席位字母 |
| 日志刷 `session_mismatch` | 跟错场次（同域有其他裁判实例） | 程序会自动切回，持续刷则核对域名 |
| 动作提交成功但不得分 | 动作方向/坐标被裁判判非法 | 立即留日志，赛后复盘，不现场改代码 |
| 网关请求失败/超时 | 网关地址不完整或网络不通 | `curl` 测网关可达性；地址补全 `/v1/chat/completions` |
| 日志显示 AI 全部失败 | 网关密钥/额度问题 | 事件理解降级，几何决策仍可用，继续比赛并报告裁判 |
| `docker: command not found` | 在容器内执行了宿主命令 | 回宿主机执行，`pwd` 确认 |
