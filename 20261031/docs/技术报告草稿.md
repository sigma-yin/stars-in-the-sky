# RMTC 图灵对决赛 技术报告

> 提交形式：语雀文档。文中不含 API Key、正式令牌、场次 ID 或地图数据；
> 练习场成绩仅用于验证策略方向，不代表正式比赛结果。

## 1. 整体设计思路

参赛程序是一个 ROS 2 Humble 节点 `rmtc_bot`，只通过官方公开接口工作：

- 订阅 `/team_<席位>/perception` 获取本场感知；
- 向 `/team_<席位>/action` 提交动作，动作回填当前感知的 `tick` 与 `session_id`；
- 随机事件只以官方自然语言公告的形式进入大语言模型，模型返回结构化建议，经几何校验后参与决策。

设计上刻意把"理解"和"执行"分开：

- **理解交给模型**：公告文本不做任何关键词匹配、模板匹配或事件时刻表，事件类型、作用区域、
  持续时间都由模型从自然语言中读出。
- **执行交给确定性代码**：模型只输出坐标与截止 Tick，所有越界、超时、区域过大的建议直接丢弃；
  具体走哪一格、打不打、撤不撤，由可复现的规则与 BFS 决定。

程序不含任何地图、资源点、事件时刻或任务坐标的硬编码；席位、ROS 域、网关地址和令牌
全部由环境变量在运行时注入，镜像内不含任何密钥。

## 2. 系统结构

```
感知 (JSON)
  ├─ 世界模型：自身位置/HP、障碍、资源、敌车（HP/防御/保护/位移）、任务、比分
  ├─ 事件公告 ──► 异步 LLM 客户端 ──► 结构化建议（avoid/stay/heal/goto/attack_all_until/priority）
  │                                        └─ 几何校验后写入本地状态
  └─ 决策器（有限优先级）
       危险区脱离 → 回血 → 驻留/无双 → 交战 → 卡位 → 任务 → 资源 → 探索 → 等待
  └─ 动作（move/attack/defend/wait）──► /team_X/action
```

代码约 1700 行，两个文件：

- `bot_node.py`：世界模型、事件状态、决策、寻路；
- `ai_client.py`：异步 LLM 客户端与系统提示词。

### 2.1 世界模型

- 障碍、资源、敌车按 9×9 相对位置换算成绝对坐标；撞过的障碍写入本地记忆，避免重复撞墙。
- 资源记忆：视野内消失即认为被取走；视野外保留，任务未完成时超过 120 Tick 丢弃；
  三项任务完成后不再按时间丢弃，转为二次收集目标。
- 敌车记录 HP、是否防御、是否处于出生保护，并记录上一步位移与观测 Tick，
  用于外推拦截点（只信 2 Tick 内的观测，位移必须是一格正交）。

### 2.2 寻路与移动

- BFS 在已知可通行格上搜到目标集合的最近路径，逐步执行。
- 禁止无意义折返：若下一格正好是上一 Tick 的位置且无资源/任务/驻留价值，改选其他方向。
- 低血时默认不进入敌人正交 1~2 格火线；只有主动狩猎/卡位且该格仅处于当前目标火线时放行。
- 脱险不是"走一步"，而是在 5 步可达范围内找威胁源更少、离敌更远的格子——十字夹击时
  走一步通常仍被另一个敌人接住。

### 2.3 LLM 事件理解

模型只输出固定 JSON：

| 字段 | 含义 |
| --- | --- |
| `avoid` | 应避开的矩形与恢复安全的 Tick |
| `stay` | 需要驻留的矩形与截止 Tick |
| `heal` | 可回血点位与最后可进入 Tick |
| `goto` | 值得前往的坐标 |
| `attack_all_until` | 范围攻击增益的截止 Tick |
| `priority` | collect / reach / survive |

约束与校验：

- 提示词要求相对时长换算成绝对 Tick；只有明确的回血/驻留区域才写进 `heal`/`stay`，
  爆炸、火线、辣椒、分裂等伤害事件只能写 `avoid`。
- 模型输出只做几何校验：越界丢弃；单矩形不超过地图 25%；`avoid` 最多 6 条且总覆盖不超过 40%；
  `heal` 最多 4 点；截止 Tick 不超过当前 Tick + 80。
- `avoid` 与 `heal` 交叉时以 `avoid` 为准，防止把伤害点当回血点。
- `attack_all_until` 只增不减，避免模型中途返回 0 清空攻击窗口。
- 请求异步执行、最多 2 个在途，不阻塞动作窗口；过旧结果按 Tick 丢弃。

### 2.4 决策优先级

1. 已在危险区内：立即走向最近的安全格；
2. HP ≤ 60 且存在有效回血点：去回血；
3. 驻留任务：区域内朝中心往返（提高 5×5 范围攻击覆盖），无双期间无敌人时继续守点；
4. 交战：一击必杀随时打；无双期间视为值得开战；其余按换血胜算决定打完还是脱离；
5. 卡位：40~60 HP 且眼前目标打不动时不漫游，先占下一枪的位置；
6. 任务：收集类优先收所需资源，到达类按时间与资源进度前往；
7. 资源：任务完成后把全图已知资源作为第二目标；
8. 探索未知区，最后原地等待。

## 3. 关键策略

### 3.1 抢资源优先

1v1 争抢同一资源时以资源为首：对手在同一资源点的路径上时，不为了"先打一枪"
让出资源位，先完成拾取再决定是否交战。早期版本因抢枪导致资源项长期不满。

### 3.2 交战与换血

- 每枪 20 点、防御当 Tick 不攻击且伤害减半（20→10）、死亡扣 60 分并以 100 HP 复活。
- 进入交战前先算换血：`本轮可打出的击杀次数 ≥ 对方所需次数` 才接；
  多敌集火时按合计火力计算——单挑能赢不代表二打一能赢。
- 伤害在本 Tick 移动前结算，所以"跑不跑都挨"：必死 Tick 先判断防御能否把自己救回来，
  救不回来就把这一击打出去。
- 防御中的敌人当 Tick 不还手，60 HP 以上且无第二敌人时白打（10 点/枪）；
  残血（≤20）防御目标两枪可补掉，低血也照打。

### 3.3 卡位（40~60 HP 时装填）

血量 40~60 时既不该撤退、也打不动满血敌人，早期版本会漫游 100 Tick 零输出。改为：

- 对 ≤20 HP 且正在防御的敌人：站进它的正交 1~2 格射击位。它当 Tick 不还手，
  站火线里也不会挨打，每 Tick 白打 10 点，4 枪补掉。
- 对 ≤60 HP 的受伤敌人：站到预判落点的侧翼，等它自己走进射程。
- 满血敌人不贴：贴上去也打不动，只会跟着绕圈（实测 50 Tick 零开火）。

### 3.4 预判拦截

用敌车上一 Tick 的位移外推 1~2 格作为接近点（距离 ≥6 格取 2 步），
只对"正在远离我们"的目标预判——迎面来的车预判反而绕远。同速追击时这一点决定了
能否在尾盘追上残血目标。

### 3.5 尾盘处理

Tick ≥ 350 后按有效伤害 D 分三段，`damage_locked` 优先于 `catch_up`：

- **D < 700（避免守点空窗）**：`fight_to_death`。20 HP 也不再守点、不再等血，
  每条命 100 HP 能换 5 枪、死亡 -60，净收益约 +40；同时狩猎下限从 30 降到 20，
  满血目标也接（`catch_up`）。实测守点会留下 120 Tick 空窗，D 卡在 650。
- **700 ≤ D < 760（收尾）**：`damage_locked`。平局保险的 700 已到手，不再开新战、
  不再跟满血对手换血，只收 ≤40 HP 的残血目标，把手上这一场打到停火线 760。
- **D ≥ 760（停火）**：到达停火线，遇敌先脱离，之后优先压死亡数。
  760 = 700 + 一次死亡余量 60：死亡一次倒扣 60，停火线必须比目标高 60，
  否则终局一死就跌回 700 以下。

## 4. 关键规则的处理

| 机制 | 处理方式 |
| --- | --- |
| 普通攻击 20、防御减半 | 只在有胜算时对拼，否则防御或按多步路线脱离火线 |
| 死亡 -60、复活保护 | 低血不主动进火线；伤害到 700 后不再开新战 |
| 天下无双（5×5 范围攻击） | 堡垒出现前提前到位；驻留时朝中心靠拢；窗口内优先攻击与狩猎 |
| 天使恩泽 | 公告出现即记录点位，满血也提前蹲守 |
| 爆炸/火线/辣椒/世界分裂 | 模型写入 `avoid`，决策层按矩形与截止 Tick 规避，不进入被覆盖的回血点 |
| 幻术（方向颠倒） | 协议无结构化字段，不做方向补偿，仅按公告区域 `avoid` 处理 |
| 洁身自好（反伤） | 未单独建模；模型判定为伤害区时按 `avoid` 规避，其余按普通防御目标处理 |
| 潘潘的神（易伤） | 按 `avoid` 与低血保守处理，未单独建模 |

## 5. 两阶段适配

- 第一阶段（100 Tick、100 ms/Tick）：BFS + 障碍记忆 + 未知区探索，练习场资源项达到满分
  （R2 180~200，得分 36~40）。
- 第二阶段（500 Tick、500 ms/Tick）：加入任务、资源、事件规避、驻留、交战、卡位与尾盘决策；
  练习场四车对局三项任务均能完成，伤害项可达 45.0 的分数上限。

同一节点按感知字段自动适配 Tick 数与时间尺度，不需要切换参数。

## 6. 策略迭代与练习场数据

四车对局（第二阶段 500 Tick、500 ms/Tick），记录"有效伤害 D / 死亡数 / 总分"：

| 版本 | 局数 | D | 死亡 | 总分 |
| --- | --- | --- | --- | --- |
| 初版（低血脱离、无卡位） | 4 | 760 / 715 / 558 / 330（均值 591） | 均值 5.25 | 2 局 45.0 |
| 加卡位 + 预判拦截 | 3 | 650 / 745 / 710（均值 702） | 6 / 6 / 8 | 3 局 45.0 |
| 加尾盘打到死（4 局） | 4 | 450 / 750 / 770 / 776（中位数 760） | 3 / 8 / 6 / 4 | 43.5 / 45.0 / 45.0 / 45.0 |
| 最终版复测（3 局，真实模型） | 3 | 760 / 690 / 815（均值 755，中位数 760） | 5 / 5 / 5 | 42.5 / 45.0 / 45.0 |

结论与遗留问题：

- 卡位与预判拦截把均值从 591 提到 702，主要来源是原来 40~60 HP 的漫游空窗变成实打实的输出。
- 最终复测三场全部 3/3 任务、无非法动作；R2 抢到 60 的两场都是 45.0，R2 只有 50 的一场 42.5——
  该场四车分完资源池，资源项封顶，与 D 高低无关。
- 尾盘"打到死"得到验证：第三场 350 Tick 时 D 只有 545，四次尾盘死亡发生在 354~441 Tick，
  450 Tick 时 D 升到 815，为本次最高。
- 遗留问题：20 HP 追击同速逃敌会陷入拉锯（450 那一局），当前用 30 HP 狩猎下限兜底，未彻底解决。

## 10. 遇到的问题与解决思路

1. **容器间感知收不到、动作却能到达裁判**
   Fast DDS 在同宿主机优先使用共享内存，容器 `/dev/shm` 不共享时会静默丢感知，
   表现为车辆全程不动。解决：镜像内提供 UDP-only 的 Fast DDS 配置并设为默认，
   不依赖 `--ipc=host` 等运行参数。

2. **同一 ROS 域混入其他裁判实例**
   其他实例发布了另一场次的感知，程序跟随错误场次，动作被判 `session_mismatch`。
   解决：中途出现 Tick 已很大的新场次时忽略；原场次连续 3 秒无感知才允许切换。

3. **低血只会后撤，伤害长期为 0**
   早期 HP ≤ 50 就脱离，撤退途中仍被打死且没有输出。解决：按换血胜算决定是否打完，
   HP > 60 主动找敌人、40~60 只追残血；后期进一步把下限统一到 30，实测抬高阈值反而更差。

4. **模型把辣椒点写成回血点**
   程序按 `heal` 前往导致连续吃火线伤害。解决：提示词明确伤害事件只能写 `avoid`，
   并增加 `avoid`/`heal` 交叉校验。

5. **无双攻击窗口被模型清空**
   模型中途返回 `attack_all_until=0`，旧逻辑直接覆盖。解决：截止 Tick 只增不减。

6. **40~60 HP 漫游空窗**
   打不动满血敌人又不敢撤，实测 156 Tick 零输出、D 只有 410。解决：卡位策略（见 3.3），
   均值 D 从 591 提升到 702。

7. **同速追击追不上**
   尾盘 20 HP 追 20 HP 逃敌 120 Tick 零输出（D 450 局）。已用拦截外推与兜底阈值缓解，
   彻底方案需要预判对方的逃跑方向选择，列为后续优化。

## 11. 复现与运行

材料目录与启动命令见提交说明：

```
submission/
├── 提交说明.md
├── 检录录屏.webm                    # 1 分 31 秒，覆盖画面 1~5
├── rmtc-team-image.tar.gz           # docker load 后用 rmtc-team:20261029 启动
├── rmtc-team-image.tar.gz.sha256
├── rmtc-team-code.tar.gz            # src + Dockerfile + 启动脚本 + 配置 + docs
└── rmtc-team-code.tar.gz.sha256
```

启动时按主办方通知注入席位、令牌、AI 网关与 ROS 网络：

```bash
docker run --rm --network host \
  -e RMTC_SEAT=A \
  -e RMTC_TEAM_TOKEN="<本场席位令牌>" \
  -e RMTC_AI_URL="<本场统一 LLM 网关完整 completions 地址>" \
  -e ROS_DOMAIN_ID=27 \
  -e ROS_LOCALHOST_ONLY=0 \
  -e RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  rmtc-team:20261029
```

后三个是镜像内默认值，显式写出是为了与提交说明逐字一致。

现场只允许修改 `decision_config.json` 的 `decision_type`（`collect` / `survive`），
程序每 20 Tick 重新读取，暂停期间修改、恢复后生效。
