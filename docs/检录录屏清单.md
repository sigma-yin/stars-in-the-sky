# 赛前检录录屏清单

目的：用**自己的程序**证明「收到感知 → 正确回填 tick/session → 提交合法动作 → 收到执行回执」。
录屏中不得出现模型 API Key 或正式令牌。

## 一、录屏前准备（不需要出现在画面里）

1. 令牌写入权限 600 的环境文件，不要在终端里 `echo` 或明文导出：

   ```bash
   install -m 600 /dev/null ~/rmtc_env
   # 在编辑器里写入：
   # RMTC_SEAT=A
   # RMTC_TEAM_TOKEN=本场席位令牌
   # RMTC_AI_URL=本场统一网关完整 completions 地址
   ```

2. 裁判已启动并处于暂停状态，页面 http://127.0.0.1:8080 可打开。
3. 确认没有残留的参赛进程或第二个裁判占用同一域：

   ```bash
   pgrep -af bot_node
   pgrep -af practice.py
   ```

## 二、录屏步骤（建议 2~3 分钟）

1. **画面 1：裁判页面**
   展示当前位置、Tick 计数、A 席位在线；此时处于暂停。

2. **画面 2：启动自己的程序**

   ```bash
   docker run --rm --network host \
     --env-file ~/rmtc_env \
     -e RMTC_MODEL=<模型名> \
     rmtc-team:latest 2>&1 | tee /tmp/precheck_bot.log
   ```

   出现 `rmtc_bot ready, seat=A` 即可。不要展示环境文件内容。

3. **画面 3：点“开始 / 继续”，让比赛跑 20~30 Tick**
   终端里应连续出现：

   ```
   tick=12 pos=(5, 5) hp=100 res=2 send={'action': 'move', 'direction': 'up'}
   ```

   说明：收到感知、解析出位置/HP/资源、按当前 tick 提交动作。

4. **画面 4：裁判执行回执**
   暂停后打开诊断页，展示 A 席位：

   - 感知 Tick 与当前 Tick 一致；
   - 动作 Tick 已被接受；
   - 无 `session_mismatch`、无 `invalid_actions`；
   - 公开感知里的 `last_action` 显示 `moved: true` 与 `effective_direction`。

5. **画面 5（可选）：命令行回执**

   ```bash
   curl -s http://127.0.0.1:8080/api/state | \
     python3 -c 'import json,sys;d=json.load(sys.stdin);print(d["status"]);print(d["checks"]["A"])'
   ```

   展示 `perception_tick`、`last_action.tick`、`moved`。

6. **结束**：暂停比赛，`Ctrl-C` 结束程序，确认日志中没有 WARN/ERROR 关键项。

## 三、自检要点

- [ ] 画面里能看到自己的程序名 `rmtc_bot`（不是参考车 `robot_node`）
- [ ] 终端日志的 `tick` 与页面 Tick 一致
- [ ] 动作被接受，`invalid_actions` 保持 0
- [ ] 展示执行回执（`last_action` / `moved`）
- [ ] 全程未出现令牌、API Key、网关密钥
- [ ] 录屏文件随代码、镜像、技术报告一起提交

## 四、常见问题

| 现象 | 处理 |
| --- | --- |
| 终端只有 `ready`、没有 tick 日志 | 检查容器是否用了镜像内置的 UDP-only 配置；同机再起容器可加 `--ipc=host` 兜底 |
| 动作全部被判 `session_mismatch` | 同域有其他裁判在发布别的场次；程序会忽略中途出现的新场次，若仍异常先关闭其他实例 |
| 页面显示已连接但车不动 | 比赛是否仍处于暂停；确认程序版本是最新镜像 |
| `RMTC_TEAM_TOKEN` 缺失 | 程序会直接报错退出，检查环境文件路径与权限 |
