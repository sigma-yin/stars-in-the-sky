## 0. 怎么读这份文档

每个"代码块"给出三层信息：

- **做什么**：这段代码在运行时完成什么动作；
- **为什么**：这个写法解决了什么问题（多数来自练习场实测的坑）；
- **关联**：和规则、和决策优先级的对应关系。

---

## 1. 整体运行链路

一帧感知的完整生命周期：

```
裁判发布 /team_A/perception (JSON 字符串)
  └─ on_perception            (281)  解析 tick / session_id，场次防护，重发缓存
      ├─ update_world         (348)  位置、HP、地图、比分、障碍、资源、敌车、被挡反馈
      ├─ apply_ai             (574)  取回模型结果 → 解析 → 几何校验 → 写入 avoid/stay/heal/goto
      ├─ maybe_ask_ai         (502)  公告增量 → 组 prompt → 发起异步请求
      ├─ hazard_cells         (489)  把 avoid 矩形展开成格子集合
      ├─ decide               (1284) 按优先级选动作（内部大量调用寻路/战斗/资源逻辑）
      ├─ avoid_backtrack      (1157) 抑制无意义折返
      └─ publish              (339)  回填 tick/session_id 发到 /team_A/action
```

一帧只产生一个动作；所有决策都是"从上到下第一个命中的分支胜出"。

## 2. bot_node.py 逐块说明

### 2.1 导入与环境变量（1–15）

| 块 | 作用 | 意义 |
| --- | --- | --- |

### 2.2 QoS 与方向表（17–29）

| 块 | 作用 | 意义 |
| --- | --- | --- |
| 17–22 | `RELIABLE + KEEP_LAST(1)` | 感知只需要最新一帧，深度 1 避免积压旧帧；可靠传输防止丢帧导致决策断档 |
| 24–29 | `DIRS`：up/down/left/right 对应 (0,-1)(0,1)(-1,0)(1,0) | 全文件唯一的坐标方向来源；屏幕坐标 y 向下，`up` 是 y 减 1 |

### 2.3 关键常量（30–49）

| 常量 | 值 | 作用与由来 |
| --- | --- | --- |
| `RESOURCE_TYPES` | `resource_normal`、`resource_high` | 感知里两种资源类型名 |
| `RESOURCE_TARGET` | 60 | 资源目标：够任务用并留余量，超过后不再为资源绕路 |
| `DAMAGE_FLOOR` | 700 | 平局保险线：到达后不再开新战，只打完手上的 |
| `DAMAGE_TARGET` | 760（700+60） | 停火线：700 之上再加一次死亡余量，终局死一次也不会跌破 700 |
| `SPRINT_TICKS` | 300 | 前期冲刺抢资源的截止 Tick |
| `LATE_TICKS` | 350 | 尾盘判定起点 |
| `CONTEST_RANGE` | 4 | 1v1 抢资源时"同一场争夺"的半径，超过就各走各的 |
| `MAX_AI_UNTIL` | 80 | 模型给的截止 Tick 最多只能超出当前 80 Tick，防止被写死到终局 |
| `MAX_AVOID_RECTS` | 6 | avoid 最多 6 个矩形 |
| `MAX_RECT_RATIO` | 0.25 | 单个矩形不超过地图 25% |
| `MAX_AVOID_RATIO` | 0.40 | avoid 总覆盖不超过 40% |
| `MAX_HEAL_POINTS` | 4 | 回血点最多采信 4 个 |

> 为什么阈值这么定：代码注释记录了实测——R2>50 单独抬升狩猎门槛到 50 HP，会让 bot 在 41~50 HP 逛街不出手，D 掉到 330~585 且死亡更多，所以最终统一成一套阈值。

### 2.4 顶层工具函数（52–199）

| 块 | 函数 | 做什么 | 为什么 |
| --- | --- | --- | --- |
| 52–63 | `relative_position` | 把 9×9 相对位置字符串里字符 `2` 的位置换算成 (dx,dy) | 感知用 9×9 文本网格表示相对坐标，`2` 是自己，中心偏移 4 |
| 66–78 | `parse_json_object` | 从模型输出里截取第一个 `{...}` 并解析 | 模型偶尔会在 JSON 前后加说明文字，直接 `json.loads` 会失败 |
| 81–88 | `as_int` | 严格取整数，bool 和 1.5 这类小数一律拒绝 | 模型可能返回 `true` 或 `3.7` 当坐标，宽松转换会让位置错位 |
| 91–96 | `as_float` | 取浮点数（有效伤害可能是小数） | 比分里的 `effective_damage` 不保证是整数 |
| 99–153 | `parse_rects` | 校验矩形列表：坐标转整、左下/右上排序、越界丢弃、单矩形 >25% 地图丢弃、总覆盖 >40% 丢弃、最多 6 条、until 缺省 tick+40 且夹在 [tick, tick+80] | 这是"模型只做理解、代码做合法性"的核心闸门；模型一次返回特大区域就会锁死全图，必须整条丢弃 |
| 156–169 | `parse_points` | 解析 goto 坐标点 | 只保留合法整数坐标，其余忽略 |
| 172–199 | `parse_heal` | 解析回血点：坐标 + 最后可进入 Tick，越界丢弃，最多 4 个 | `heal` 只采信模型明确给出的点；缺省 20 Tick 有效期，同样夹在 80 以内 |

### 2.5 节点初始化与会话复位（202–263）

| 块 | 作用 | 意义 |
| --- | --- | --- |
| 205 | 创建发布者 `/team_A/action` | 席位号来自环境，不同席位话题不同 |
| 206–208 | 订阅 `/team_A/perception`，回调 `on_perception` | 唯一的数据入口 |
| 209 | 创建 `AIClient` | 异步请求，不阻塞回调 |
| 210–212 | 读 `RMTC_DECISION_CONFIG` | 现场只需替换这一个 JSON 文件 |
| 213–220 | 记录 session、上次动作、地图尺寸（默认 20×20），调用 `reset_session` | 场地尺寸以感知为准，默认值只是兜底 |
| 223–263 | `reset_session` | 每开一个新场次就清空全部状态，避免上一场的敌车/资源记忆污染本场 |

`reset_session` 里几个值得单独看的字段：

- `pressing`（231）：卡位时允许踩进防御目标的火线，`passable` 会据此放行；
- `blocked_until`（236）：`E_BLOCKED` 只是单帧结果，不能写成永久障碍，否则一次抢格失败就毒掉整条路径；
- `enemy_vel`（241）：敌车上一步位移，用于预判拦截，只信 2 Tick 内观测；
- `combat_done`（258）：有效伤害达到 760 后的全局停火标志；
- `pending`（259）：上一 Tick 发出的移动，用于下一帧核对"到底动没动"。

### 2.9 告警区展开 `hazard_cells`（489–500）

把 `avoid` 矩形按当前 Tick 过滤后展开成格子集合，同时顺手回收过期矩形。
意义：把"矩形 + 截止 Tick"统一成"格子集合"，寻路和安全判定只需一次集合查询，避免每处重复展开。

| --- | --- | --- |
| 1110–1127 | `contested_resource`：视野里只有一辆敌车，且某资源我们更近（或同时到）、在 4 格内 | 1v1 抢同一资源时踩到就是确定的资源分，换一枪只有 20 伤害 |
| 1129–1135 | `short_goals`：资源 + reach + goto 的可通行子集 | 折返抑制的"前方目标"集合 |

### 2.19 路径工具与折返抑制（1137–1190）

| 块 | 作用 | 意义 |
| --- | --- | --- |
| 1137–1155 | `bfs_distance`：到目标集合的最短步数 | 折返抑制要比较"走折返"和"绕行"的剩余路程 |
| 1157–1190 | `avoid_backtrack`：若下一步正好是上一帧位置且该格无价值，就比较两条路，只有绕行更短才改道 | 折返格常在最短路上，一票否决会把 bot 挤向反方向（实测丢第 4 个资源）；`urgent`（脱险）时完全不过滤 |

### 2.20 战斗动作（1192–1282）

`combat_action` 是分层判断，顺序即优先级：

| 块 | 判断 | 动作 |
| --- | --- | --- |
| 1211–1212 | 眼前没有可打的敌人 | 返回 None，交给后续分支 |
| 1214–1217 | D 已到 760 | 先脱险，否则防御 |
| 1219–1220 | 自己处于出生保护 | 不主动攻击 |
| 1222–1225 | `kill_target`：一击可杀（防御按 10 判），或敌人 ≤40 且自己 >40 | 直接攻击（回报确定） |
| 1235–1237 | 无双增益有效期内 | 直接打，窗口内每枪收益翻倍 |
| 1239–1253 | 单一威胁且目标在防御，自己 >60（或目标 ≤20 两枪可杀） | 白打防御目标——它当 Tick 不还手 |
| 1255–1262 | 换血：`敌人所需枪数 ≤ 我能打出的枪数`（按合计火力算） | 有胜算就打 |
| 1264–1272 | 本 Tick 必死 | 防御能救（HP > 一半）就防御，救不了就把这一击打出去；尾盘 D<700 时一定打 |
| 1274–1282 | 换血亏 | 多步脱险，实在无路才防御减半 |

`kill_target`（1192–1208）单独看：一次遍历按敌方 HP 升序，优先补刀；`dmg` 对防御目标取 10，避免误判"一击必杀"。

### 2.21 总决策 `decide`（1284–1508）

按顺序命中即返回，这就是"决策优先级"的代码形态：

| 块 | 条件 | 行为 | 意义 |
| --- | --- | --- | --- |
| 1285–1291 | 已死亡 / 自身不可见 | wait | 复活前不发无效动作 |
| 1293–1294 | — | 清掉脚下资源记忆 | 踩到即拾取，记忆跟着更新 |
| 1297–1306 | 当前格在告警区内 | 走向最近安全格 | 事件伤害按区域结算，原地等会持续掉血 |
| 1312–1315 | HP ≤ 60 且无双未激活 | 去回血 | 死一次 -60，回血优先；无双窗口内不打断抢攻 |
| 1317–1328 | 在驻留区内 | 累计 `bastion_ticks`；不足 12 或无双未生效或无敌人时继续守点 | 堡垒要攒满 10 Tick 才有无双，提前跑出去等于全程普攻 |
| 1332–1342 | Tick ≥ 320、只剩 reach、HP > 50 | 提前去踩点 | 踩点是确定的任务分，不需要停留 |
| 1346–1355 | 非无双、HP > 60、R2 < 60 | 1v1 抢资源优先 | 资源是确定加分，且只有一辆敌车不怕夹击 |
| 1359–1375 | 非无双、HP > 80、Tick ≤ 300、R2 < 60、眼前无敌人 | 全图捡资源；无资源时去 goto/未知区 | 前期资源分权重高，4 车同图不抢就被拿完 |
| 1377–1390 | 有任务且非 survive 模式 | 无双攻击 → 狩猎 → 回血 → 交战 | 任务期的主战斗链，顺序即优先级 |
| 1394–1402 | 任务完成、无资源、HP > 80 | 提前去天使点蹲守 | 受伤后能立刻进点回血，省往返 |
| 1407–1416 | HP ≤ 20、任务完成、无回血点、非尾盘 | 有敌人防御，否则等待 | 20 HP 游走等于送 -60；尾盘例外（守点换不到伤害） |
| 1418–1425 | reach 未完成且 Tick ≥ 380 或 R2 ≥ 120 | 去 reach 点 | 尾盘兜底，避免被追打错过 |
| 1430–1445 | — | 资源目标：按任务类型收窄；任务后只拿 8 格内；冲刺期不设限 | 平衡"捡资源"和"打伤害"的路程成本 |
| 1448–1456 | 非无双、非 survive、有敌人、`should_hunt` | 追打可见敌人 | 有目标先贴上去，别被 goto 拉走 |
| 1460–1467 | 非无双、非 survive、有敌人 | 卡位 | 打不动的目标也要占好下一枪位置 |
| 1470–1478 | 非无双、非 survive、无敌人、任务完成 | 追记忆点 | 视野外靠记忆找人，提高接战次数 |
| 1480–1483 | reach 仍存在 | 去 reach | 常规兜底 |
| 1485–1489 | 任务未完成 | 去 goto 点 | 模型给的可疑点/任务相关点 |
| 1494–1504 | 无敌人、未到保险线、Tick > 300 | 往地图中心 | 四角出生只有中心会反复相遇；沿边缘探索实测空转 130 Tick |
| 1506–1508 | 兜底 | 探索未知边界，否则等待 | 永远有合法动作返回 |

### 2.22 通行性与探索（1510–1543）

| 块 | 作用 | 意义 |
| --- | --- | --- |
| 1510–1528 | `passable`：越界/障碍/敌车/临时禁行/告警区一律不可走；低血（>60 保险线后为 60，否则 50）不进敌人火线，但狩猎/卡位时放行当前目标火线 | 一个函数统一所有寻路的合法性，狩猎与卡位的"特许通行"也在这里 |
| 1530–1543 | `frontier`：已知可走格的相邻未知格 | 探索目标；排除障碍与告警区 |

### 2.23 BFS 与动作生成（1545–1607）

| 块 | 作用 | 意义 |
| --- | --- | --- |
| 1545–1565 | `bfs_to_any`：到目标集合的最近路径，边走边判 `passable` | 所有移动都走这里，通行规则只维护一处 |
| 1567–1571 | `next_move`：路径不足 2 格视为"没有动作"，返回 None | 让调用方继续尝试下一个目标，而不是原地 wait |

## 7. 合规要点（对照规则）

- 事件理解只走 LLM：`maybe_ask_ai` 只把 `event_text` 原文交给模型，代码里没有关键词匹配、正则或事件时刻表。
- 模型输出只做几何校验：`parse_rects / parse_heal / parse_points` 只判断越界、面积、数量、时间上限，不推断事件类型。
- 不硬编码场地：地图尺寸、任务、资源、敌车全部来自感知。
- 不硬编码密钥：席位/令牌/网关/域全部环境变量注入，镜像内 `env` 无任何令牌。
