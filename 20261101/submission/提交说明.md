## 本轮变更（相对 20261031 递交的 `rmtc-team:20261029`）

共 11 条改动，另修掉一处新版自身的崩溃：

1. AI 请求超时 5 s → 8 s，可用 `RMTC_AI_TIMEOUT` 覆盖；
2. 单个 AI 请求记录耗时与失败类别（timeout / error）；
3. 超时退避上限 30 Tick，限流/报错仍 60 Tick；
4. AI 建议时效按字段分级：`avoid` 20 Tick，`stay/heal/goto/attack_all_until` 40 Tick；
5. 新增 `EDGE_TICKS` / `CENTER_RADIUS` / `CENTER_EXIT_TICKS` 三个常量；
6. 开局贴边判定（距边界 ≤1 格）与首个资源到手 Tick 记录；
7. 寻路邻居顺序改为先横后竖且朝地图中线，贴边开局未吃到资源时反过来；
8. 探索/找资源优先选「离中心不比当前更远」的格子，缩不进去才放开全部候选；
9. 中心 2 格内无目标时定向离开 20 Tick，途中见资源或敌人立即退出；
10. 所有目标不可达时改为挑周边最空的相邻格脱困，不再顶着墙 `wait`；
11. `detour_action` 解包写错（`TypeError: cannot unpack non-iterable int object`，会直接崩节点）
    改为 `{增量: 方向名}` 反查表。

前因与解释见 [`../docs/今日改动说明_20261101.md`](../docs/今日改动说明_20261101.md)。

## 导入与启动

```bash
gunzip -c rmtc-team-image.tar.gz | docker load
docker images rmtc-team --format '{{.Repository}}:{{.Tag}} {{.ID}}'   # rmtc-team:20261101 21930139bd78
```

席位、令牌、网关、ROS 网络均按主办方现场通知通过环境变量注入：

```bash
docker run --rm --network host \
  -e RMTC_SEAT=A \
  -e RMTC_TEAM_TOKEN="<本场席位令牌>" \
  -e RMTC_AI_URL="<本场统一 LLM 网关完整 completions 地址>" \
  -e ROS_DOMAIN_ID=27 \
  -e ROS_LOCALHOST_ONLY=0 \
  -e RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  rmtc-team:20261101
```

- 未提供 `RMTC_TEAM_TOKEN` 时程序打印提示并以退出码 2 终止，不会空跑。
- 镜像内不含任何令牌、密钥或练习场次数据。
- `decision_config.json` 已打包进镜像，仅含 `decision_type`（`collect` / `survive`），
  每 20 Tick 重读，暂停期间修改、恢复后生效。
- 可选 `-e RMTC_AI_TIMEOUT=8`（秒）。现场网关更慢时可上调，但一条建议只在 20 Tick
  （500 ms/Tick 下约 10 s）内有效，超过 8 s 再等只会拿到过期建议。
